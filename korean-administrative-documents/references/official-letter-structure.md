# Korean official-letter structure

Use this reference for 공문, 시행문, and cover letters submitted to a Korean public institution. A private contractor is not automatically bound by every administrative-agency rule, but this structure is the strongest design reference for a document that must look like a public-sector official letter.

## Authoritative references

- Ministry of the Interior and Safety, *2025 행정업무운영 편람*: https://www.mois.go.kr/frt/bbs/type001/commonSelectBoardArticle.do?bbsId=BBSMSTR_000000000012&nttId=122878
- `행정업무의 운영 및 혁신에 관한 규정 시행규칙`: https://law.go.kr/LSW/lsInfoP.do?lsId=007319
- Page-number provision: https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1023619797

Verify the current source if the legal or procedural detail materially affects submission acceptance.

## Recommended topology

1. Sender organization name or approved letterhead
2. `수신` and optional `경유`/`참조`
3. `제목` describing the actual submission
4. Numbered body paragraphs
5. Attachment list
6. Sender name and seal position
7. Closing block with verified document number, date, address, and contact details
8. Centered page number

Do not add a large standalone `문서` title. Do not place the metadata in a visually dominant blue form table.

## Attachment list

Use one row per item. Align the numbers with a fixed tab stop or a borderless three-column table:

| Label | No. | Item |
|---|---:|---|
| 붙임 | 1. | 첫 번째 자료 1부 |
|  | 2. | 두 번째 자료 1부 |
|  | 3. | 최종산출물 일체 1식.  끝. |

Never align the list with repeated spaces. Keep the `붙임` subsection heading left-aligned.

## Sender and seal

Use the verified legal entity and representative title. Keep the seal placeholder adjacent to, or positioned over, the relevant end of the sender name according to the template. Do not use a large run of spaces between the representative and `(직인)`. Do not claim that a seal or signature has been applied when it has not.

## Closing metadata

Only include known values. If a telephone number or email address is unavailable, omit it or leave it explicitly unresolved in a working draft. Never insert placeholders such as `02-0000-0000` into a deliverable.
