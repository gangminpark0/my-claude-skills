# Prompt Library

These prompts are starting contracts. Replace bracketed fields and keep any explicit user instruction authoritative.

## 1. Plan a new lecture

```text
다음 자료를 바탕으로 [학습자] 대상 [강의 시간/차시] 강의를 설계해줘.

강의의 큰 질문: [질문]
강의 후 학생이 할 수 있어야 하는 일: [설명/판단/비교/설계]
학생의 선행지식과 예상 장벽: [내용]
앞 차시에서 이어지는 질문: [내용]
다음 차시로 넘길 질문: [내용]
반드시 사용할 근거·사례: [목록]
반드시 보존할 수치의 분모·시점·조건·예외: [목록]
사용 가능한 기존 자료·도표·템플릿: [목록]
형식 제약: [장수, 화면비, 언어, 접근성, 출처 정책]

먼저 다음만 제안해줘.
1. 전체 서사 한 문단
2. 구간별 핵심 질문과 학습 기능
3. 슬라이드별 주장형 제목, 교육 기능, 핵심 근거, 예상 오개념, 다음 장이 필요한 이유
4. 설명이 먼저 필요한 전문용어와 이를 위한 연결 장표
5. 중복되어 삭제 가능한 내용
6. 마지막에 회수할 판단 도구와 적용 문제

정보를 나열하지 말고 경험/문제 → 질문 → 필요한 개념 → 근거/사례 → 판단 도구 → 적용 → 다음 질문의 흐름으로 설계해줘. 장수는 목표를 위한 제약이지 채워야 할 숫자가 아니다.
```

## 2. Audit and restructure an existing deck

```text
현재 PPTX가 사용자가 직접 수정한 최신 기준본이다. 먼저 백업과 SHA-256을 기록하고, 기존 화면·내장 노트·원고·출처 기록을 대조해 사용자의 직접 편집을 식별해 보호해줘. 전체 재빌드로 덮어쓰지 말고 변경 범위를 먼저 제안해줘.

모든 슬라이드에 대해 다음을 점검해줘.
- 이 장의 교육 기능과 핵심 결론이 분명한가
- 필요한 개념이 설명 전에 등장하지 않는가
- 앞뒤 전환에서 무엇이 왜 바뀌는지 알 수 있는가
- 화면의 차트·그림·분류와 노트 설명이 실제로 일치하는가
- 표본·분모·시점·법적 조건·사례 귀속이 결론과 맞는가
- 제작 메모, 번역투, 방어형 캡션, 중복 사례가 남아 있는가
- 추가해야 할 연결 장표와 삭제해야 할 장표가 있는가

먼저 슬라이드별 KEEP / REVISE / ADD-BEFORE / DELETE 판정과 이유를 표로 제시하고, 승인된 변경만 최신 PPTX 위에 최소 수정으로 반영해줘. 삽입·삭제 뒤에는 페이지, 노트, 출처 footer와 원천 매핑을 함께 갱신해줘.
```

## 3. Write read-aloud speaker notes

```text
다음 슬라이드 화면과 앞뒤 장표를 바탕으로 강사가 그대로 읽어도 자연스러운 한국어 발표자 노트를 써줘.

학습자: [대상]
이 장의 핵심 질문 또는 결론: [내용]
앞 장에서 이어지는 내용: [내용]
다음 장이 필요한 이유: [내용]
반드시 유지할 사실·수치·조건·예외: [내용]
처음 등장하는 용어·인명·기관: [내용]
노트 메타데이터 정책: [예: 시간·URL·출처 목록은 별도 기록으로 분리]

요구사항:
- 화면 위치와 도형을 읽지 말고 의미와 관계를 설명한다.
- 결론을 방법명·연도·표본보다 먼저 말한다.
- 낯선 용어는 쉬운 역할을 먼저 설명한 뒤 이름을 소개한다.
- 숫자는 무엇을 잰 값인지, 분모, 시점, 추정/전망/실적 여부와 해석을 자연스럽게 붙인다.
- 큰 전환은 무엇이 왜 바뀌는지 말한다.
- 보고서체, 번역투, 제작자 메모, 방어적 면책 문장을 피한다.
- 한 문장에는 중심 생각 하나를 두고, 응집된 문단으로 쓴다.
- 화면에 없는 지도·사진·카드·화살표를 언급하지 않는다.
- 사실 조건은 줄이지 말되 검수 보고서처럼 나열하지 않는다.

출력은 강사가 말할 본문만 제공해줘. `도입:`, `설명:`, `[시간]`, `출처:`, URL, DOI, 무대지시는 넣지 마.
```

## 4. Simplify a technical or legal slide

```text
이 장표는 정확하지만 학생에게 너무 어렵다. 다음 순서로 다시 설계해줘.

1. 학생이 기억해야 할 결론 한 문장
2. 판단을 위해 필요한 주체·대상·행동·시점
3. 답을 바꾸는 핵심 조건과 예외
4. 학생이나 조직이 실제로 확인할 질문
5. 화면에는 남길 최소 문구와 노트에서 풀어 쓸 내용

법률 조문 번호, 약어, 제품 경로, 기관명은 결론을 이해하는 데 필요한 만큼만 화면에 두고 처음 등장할 때 쉬운 설명을 붙여줘. 적용 예정인 규칙을 현행처럼 말하지 말고, 법정 상한을 실제 부과액처럼 말하지 마. 단순화를 이유로 주체·적용일·조건·예외를 없애지 마.
```

## 5. Learner-perspective review

```text
이 최종 후보를 실제 설문이 아닌 구조화된 가상 학습자 검토로 점검해줘. [초심자, 비전공자, 전공자, 한국어가 익숙하지 않은 학습자, 수치 회의론자, 실무 관심자, 사례 중심 학습자, 모바일 학습자, 거버넌스 관점, 강사 낭독 관점] 중 이 강의에 맞는 관점을 선택해.

R1에서는 전체 화면과 노트를 처음부터 읽고 다음 후보를 기록해줘.
- 용어가 설명 전에 등장함
- 전환 이유를 알 수 없음
- 결론보다 방법·표본·도구가 먼저 나옴
- 화면과 노트가 다름
- 수치나 법적 조건을 잘못 일반화할 위험
- 반복, 번역투, 지루함, 낭독 호흡 문제

R2에서는 해당 장과 앞뒤 맥락을 다시 제시한 뒤에도 남는 오개념만 결함으로 확정해. 단순히 용어를 기억하지 못한 것과 잘못 이해한 것을 구분해. 실제 학생을 초청했다고 표현하지 마.

P0는 사용 불가·위험·중대 사실/법률 오류, P1은 학습 오해·사용자 편집 유실·동기화 실패, P2는 국소적 명료성·표현·시각·재현성 결함으로 판정해. 각 결함은 등급, 슬라이드 번호, 학생이 어떻게 오해하는지, 최소 수정안으로 보고해. 수정 후 파일 해시가 바뀌면 기존 무결함 연속 기록은 초기화해.
```

## 6. Frozen-output release audit

```text
현재 후보를 더 수정하지 말고 읽기 전용으로 점검해줘. 시작 SHA-256을 기록하고 종료 시 다시 확인해. 자동검사 한 종류를 반복하지 말고 다음 독립 층을 분리해 검증해.

1. PowerPoint 실제 렌더: 잘림, 겹침, 저대비, 고아줄, 정렬, 화살표 접점
2. 학습자 흐름·이해·낭독
3. 사실·법률·출처·주장 강도
4. ZIP/XML/relationship/notes/원천 동기화
5. 사용자 지시 체크리스트 교차대조

P0는 사용 불가·위험·중대 사실/법률 오류, P1은 학습 오해·사용자 편집 유실·동기화 실패, P2는 국소적 명료성·표현·시각·재현성 결함이야. 각 층은 P0/P1/P2와 exact fix를 보고해. 결함이 하나라도 나오면 그 회차는 실패이고, 수정 후 새 해시에서 처음부터 다시 세어. 동일한 최종 해시에서 모든 요구 회차가 0건일 때만 완료로 판정해.
```
